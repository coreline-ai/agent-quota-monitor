# Provider 지원 여부를 최상위 CLI help만으로 판정하지 않는다

## 적용 범위와 비적용 조건

중첩 subcommand, JSON-RPC 또는 공식 client 내부 read-only 계약을 조사하는 Provider capability 검사에 적용한다. 최상위 command 자체가 완전한 machine contract를 직접 공개하는 경우에는 비적용할 수 있다.

## 관측 사실과 영향

Grok 최상위 help에 usage·quota·billing command가 없다는 이유로 상태 전용으로 판정했다. 이후 중첩 agent stdio, 설치 binary의 billing marker, 공식 client source의 read-only billing handler를 확인하면서 LIVE adapter 구현과 문서 판정을 다시 수행해야 했다.

## 근본 원인·기여 요인·근거

capability 검사가 최상위 help의 command 이름만 공식 계약의 전체 표면으로 가정했다. 중첩 help, generated schema, 설치 artifact marker, 공식 source, 실제 read-only 응답을 독립 증거로 조사하지 않은 것이 직접 원인이다.

## 해결과 예방 control

Provider를 미지원으로 확정하기 전에 최상위와 중첩 help, schema 또는 protocol surface, 설치 artifact marker, 공식 source를 순서대로 확인한다. 후보 계약을 찾으면 모델 호출이나 credential 변경이 없는 redacted read-only probe로 실제 사용 가능성과 method 부재를 구분한다. 단일 증거만으로 수치 계약을 만들지 않는다.

## 검증

safe validation 테스트가 최상위 quota command가 없어도 중첩 agent stdio와 billing marker를 별도로 발견하는지 검증한다. billing marker가 없을 때 observed 계약을 생성하지 않는 회귀 테스트도 함께 실행한다. 실제 Grok 검증에서는 ACP method 부재와 first-party billing backend 성공을 서로 다른 결과로 기록했다.

## 발생 정보

OCC-GROK-001, 2026-08-16 KST. 잘못된 상태 전용 판정으로 Grok LIVE 연결이 누락되고 README·Provider 계약·QA 문서를 교정하는 material rework가 발생했다.

## 검토와 예외

공식 client의 command 구조나 billing 계약이 변경될 때 재검토한다. 예외적으로 수치 연결을 보류할 때도 조사한 증거와 보류 이유를 Provider 계약 문서에 남긴다.
