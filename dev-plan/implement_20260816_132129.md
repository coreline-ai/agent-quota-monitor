## 개발 목적

TokenRemain을 기준선으로 삼아 **Codex·Claude Code·Grok Build·Z.ai GLM Coding Plan 전용 macOS AI 사용량 모니터**를 구현한다.

완료 제품은 다음을 만족해야 한다.

- macOS 메뉴 막대에서 네 Provider의 quota 상태를 빠르게 확인한다.
- 구독 quota와 로컬 토큰·비용 추정을 명확히 분리한다.
- 모든 표시 값에 출처, 관측 시각, 최신성, 오류·부분 성공 상태를 보존한다.
- 인증정보와 사용량 데이터는 로컬에서만 처리한다.
- 원본 브랜드·비오픈소스 에셋을 포함하지 않는다.
- 테스트, Developer ID 서명, 공증, 자동 업데이트 검증을 통과한 직접 배포 빌드를 만든다.

책임 경계:

- `Providers`는 원격 quota 정규화만 담당한다.
- `LocalUsageSource`는 로컬 로그·토큰·가격 추정만 담당한다.
- `Stores`는 마지막 정상 값, history, preferences를 보존한다.

- 원본 Provider payload 전체는 영구 저장하지 않는다.
- shared logic은 timeout, redaction, ratio validation, timestamp parsing처럼 실제 중복이 있는 경우에만 추출한다.

## Provider 계약 기준

| Provider | 1차 수집 | fallback | 출시 기본 상태 | 금지 동작 |
|---|---|---|---|---|
| Claude Code | 공식 statusline `rate_limits` 또는 upstream의 읽기 전용 OAuth 경로 | CLI가 이미 제공한 로컬 상태, 마지막 정상 캐시 | fixture 충족 시 Stable | 모델 호출, token 갱신·write-back |
| Codex | 기존 `auth.json` 읽기 전용 OAuth 사용량 | `codex app-server` RPC, 마지막 정상 캐시 | Beta | access/refresh token 갱신, 웹 쿠키 |
| Grok Build | `grok login` 로컬 OAuth 기반 CLI billing | 지원되는 CLI RPC, 마지막 정상 캐시 | Beta | grok.com 쿠키/WebView, Team 값을 개인 quota로 오표시 |
| Z.ai GLM | 사용자가 입력한 Coding Plan 키로 quota 조회 | 마지막 정상 캐시 | Beta | 모델 호출, 알 수 없는 limit type 무시 |

공통 규칙:

- 공개 문서가 있는 계약과 upstream에서 관찰된 비공개 계약을 `SourceContractKind`로 구분한다.
- 계정은 인식되지만 quota가 없으면 퍼센트를 만들지 않는다.
- 부분 응답은 있는 창만 갱신하고 누락된 창의 상태를 별도로 기록한다.
- Beta Provider의 수집 실패는 앱 전체 실패로 처리하지 않는다.
- fixture와 계약 문서에는 수집일, CLI/app 버전, schema fingerprint를 남긴다.

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트와 완료 조건이 모두 체크된 후에만 시작한다.
- 구현 중 발생한 이슈는 해당 Phase에서 수정하고 사실 기반으로 기록한다.
- 체크박스 상태를 실제 진행 상태와 맞게 업데이트한다.
- 문서에 없는 Provider, 플랫폼, 백엔드 기능을 추가하지 않는다.
- 불명확한 요구는 임의 확장하지 않고 `확인 필요 사항 / 결정 기록`에 남긴다.
- 한 기능은 유지보수 가능한 최소 책임 단위로 나눈다.
- 계획 밖 옵션을 위한 추상화와 범용 plugin framework는 만들지 않는다.
- 기존 upstream 코드, 공식 SDK, 표준 라이브러리를 우선 사용한다.
- 새 의존성은 기존 코드로 해결할 수 없고 라이선스 검토가 끝난 경우에만 추가한다.
- Provider endpoint 문자열, credential path, timeout은 adapter/configuration 경계에 모은다.
- 비밀정보가 포함될 수 있는 payload를 issue, fixture, 로그, snapshot에 그대로 남기지 않는다.
- 모든 ratio는 내부에서 `0.0...1.0`으로 정규화하고 범위를 벗어나면 파싱 오류로 처리한다.
- `usedRatio`를 정본으로 보존하고 `remainingRatio`는 계산한다.
- material impact·재발 위험·QA escape·보안/개인정보/무결성 near-miss·큰 재작업만 occurrence 후보로 기록한다.
- 개발 종료 전 후보를 `plan-only | existing-reference | new-lesson`으로 분류한다.
