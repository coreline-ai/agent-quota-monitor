# Expect의 반복 terminal 응답은 전체 timeout timer를 재시작하지 않는다

## 적용 범위와 비적용 조건

Expect 또는 유사 PTY transport로 interactive CLI의 read-only 화면을 수집하면서 terminal capability query에 exp_continue로 응답하는 Provider adapter와 검증 probe에 적용한다. 단일 비대화형 명령이나 exp_continue를 쓰지 않는 transport에는 비적용한다.

## 관측 사실과 영향

동일한 Antigravity CLI /usage 수집이 대부분 수 초 안에 성공했지만 설치 Release와 UI 검증 중 일부 시도는 외부 38초 제한까지 종료되지 않아 timeout으로 기록되었다. 같은 로그인과 workspace에서 즉시 재시도하면 성공해 간헐적인 연결 실패가 사용자 화면에 노출되었다.

## 근본 원인·기여 요인·근거

terminal capability query를 처리하는 Expect branch가 일반 exp_continue를 사용해 패턴이 반복될 때 현재 expect timeout timer를 처음부터 재시작했다. TUI가 query를 반복하면 내부 22초와 12초 제한이 사실상 연장되어 외부 ProcessRunner timeout까지 도달했다. exp_continue -continue_timer 적용 후 동일 read-only probe 3회 연속 성공과 timer-contract 테스트로 확인했다.

## 해결과 예방 control

bounded TUI automation에서 progress가 아닌 protocol/capability 응답 branch는 exp_continue -continue_timer를 사용해 단계의 wall-clock 제한을 보존한다. 내부 단계 timeout과 약간 더 긴 외부 process timeout을 함께 두고, 종료 시 TERM 뒤 bounded KILL fallback과 wait를 적용한다. script에 일반 exp_continue가 다시 들어가지 않도록 Swift와 Python 테스트로 고정한다.

## 검증

Swift 테스트는 six terminal query branch가 모두 -continue_timer를 쓰고 KILL fallback이 있음을 확인한다. Python probe 테스트도 동일 invariant를 확인하며 실제 /usage probe는 계정정보나 비율을 출력하지 않은 채 주간·5시간 계약으로 3회 연속 성공했다. 최종 설치 Release history에서 available, sharedWeekly와 fiveHour, officialCLI/observed/live를 확인한다.

## 발생 정보

OCC-GEMINI-003, 2026-08-17 KST. 설치 Release 검증에서 최근 Gemini attempt가 38초 후 timeout으로 끝나 connection result 확인이 실패했다.

## 검토와 예외

Antigravity CLI terminal protocol, ready marker, usage 화면 또는 공식 machine-readable usage contract가 변경될 때 재검토한다. 공식 비대화형 계약이 제공되면 PTY 자동화보다 이를 우선한다.
