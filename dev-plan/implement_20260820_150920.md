## 개발 목적
Provider 순서 기능의 남은 persistence·visibility·필터 회귀 검증과 현재 디스크 패치를 포함한 릴리스 완료 게이트를 마감한다.

## 개발 범위
기존 ProviderDisplayOrder와 설정 UI를 유지하며 UI persistence 회귀를 보강하고, Release build·전체 QA·문서 상태를 현재 결과와 일치시킨다.

## 제외 범위
- 새 Provider 또는 quota 계약 변경
- credential, network, refresh, history, notification pipeline 변경
- 새 외부 dependency 또는 기능 확장

## 마감 기준과 제약
- UI 테스트 전용 초기화 훅으로 테스트 앱의 `UserDefaults`만 결정적으로 초기화한다. 일반 실행과 저장 형식은 변경하지 않는다.
- Provider 순서는 표시 계층에서만 적용한다. refresh, credential, history, notification, provider 계약에는 손대지 않는다.
- `ProviderDisplayOrder` 적용 뒤 visibility·scope 필터를 적용했을 때 상대 순서가 유지되는 것을 단위 테스트로 고정한다.
- Universal Release 빌드와 ad-hoc 패키징까지는 이 작업에서 수행한다. Developer ID 서명·notarization·외부 배포/클린 계정 설치는 인증서와 배포 권한이 필요한 별도 운영 게이트로 기록만 하며, 완료로 주장하지 않는다.
- 이전 계획(`implement_20260819_082840.md`)은 당시 이력으로 보존한다. 이번 문서가 남아 있던 검증 항목의 최신 상태를 대체한다.
