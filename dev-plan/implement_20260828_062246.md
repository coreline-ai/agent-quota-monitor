## 개발 목적

메뉴바 popover의 수동 새로고침이 실제 최신 Provider 값을 요청하도록 자동 수집과 분리하고, macOS `동작 줄이기` 설정에서도 갱신 시작·진행·완료를 사용자가 분명히 확인할 수 있게 한다.

## 개발 범위

- 자동·popover 주기 수집은 기존 캐시 및 rate-limit 보호 정책을 유지한다.
- 사용자 수동 새로고침은 Claude·Gemini·Z.ai의 성공 캐시 최소 간격을 우회한다.
- Claude `429 Retry-After` 등 Provider가 명시한 backoff는 수동 요청도 우회하지 않는다.
- 메뉴바, 대시보드, 상태바 우클릭 메뉴의 사용자 새로고침 의미를 동일하게 맞춘다.
- 일반 모드에서는 갱신 중 계속 회전하고, `동작 줄이기`에서는 정적 상태 변화로 진행을 표시한다.
- 마지막 완료 시각을 초 단위로 표시해 같은 분 안의 재수집도 식별할 수 있게 한다.

## 제외 범위

- Provider endpoint, credential, parser 및 quota 계산 계약 변경
- `429` 또는 서버 backoff 강제 우회
- 자동 갱신 주기 변경
- 새 외부 dependency
- 사용자가 중단을 요청한 반복 XCTest/XCUITest 및 전체 감사 스크립트 실행

## 최종 결과 요약

- 메뉴바·대시보드·설정·우클릭 메뉴의 사용자 새로고침은 `userInitiated` 수집으로 통일했다.
- Claude·Gemini·Z.ai는 사용자 수집에서 성공 캐시를 우회하고, scheduled 수집에서는 기존 캐시 간격을 유지한다.
- Claude 429 `Retry-After`/기본 backoff는 수동 요청에서도 유지한다.
- 일반 모드는 갱신 완료까지 회전하며, Reduce Motion은 정적 hourglass와 `데이터 갱신 중…` 문구를 표시한다.
- 빠른 수동 수집에도 450ms 피드백을 보장하고 완료 시각을 초 단위로 표시한다.
- XCTest/XCUITest 없이 warnings-as-errors Universal Release build를 완료하고 현재 Mac의 `/Applications/QuotaBeacon.app`을 교체했다.

## 잔여 리스크 / 후속 과제

- Provider 자체 rate limit 또는 CLI timeout 중에는 수동 갱신도 해당 typed failure를 반환한다. 이는 안전 계약상 의도된 동작이다.
- Developer ID 서명과 notarization은 현재 Mac 로컬 배포 범위 밖의 운영 게이트로 남는다.
