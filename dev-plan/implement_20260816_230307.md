이 문서는 QuotaBeacon의 Z.ai GLM Coding Plan 연결을 공식 Usage Query 플러그인 기반으로 구현하는 범위를 고정하고, 실제 계정 수치가 화면에 나타날 때까지 원인 분석·수정·검증하기 위한 작업 문서다.

## 개발 목적

현재 `unsupportedContract` 상태로 고정된 Z.ai GLM을 사용자가 이미 쓰는 `claude-glm` 프로필과 Z.ai 공식 `glm-plan-usage` 플러그인에 연결한다. 비밀값이나 원본 payload를 저장하지 않고 공식 플러그인 실행 결과의 quota section만 정규화하여 메뉴·개요·한도·추세 화면에 실제 사용률을 표시한다.

## 개발 범위

- `claude-glm` zsh alias의 허용된 환경 변수 이름·값을 read-only로 자동 탐지하는 profile reader
- Claude Code에 설치된 공식 `glm-plan-usage@zai-coding-plugins` cache script 자동 탐지
- 공식 plugin script를 정확히 1회 실행하고 quota section만 분리하는 process adapter
- GLM 5시간 token quota와 월간 MCP quota parser 및 provenance
- 연결 화면의 GLM opt-in, 탐지 증거, 적용 결과 GUI
- 데이터 소스·README·Provider 계약·보안·검증 문서 갱신
- synthetic parser/profile fixture, unit test, redacted 실계정 probe, XCUITest screenshot
- Release 빌드, 개인 앱 재설치·실행, Coreline-ai 원격 main 반영

## 제외 범위

- Z.ai credential 또는 shell profile 생성·수정·로그인·refresh
- 모델 endpoint 호출, prompt 전송, 대화 시작
- 공식 plugin source·fixture·UI·asset을 제품 저장소로 복사
- 지원되지 않은 Coding Plan 모델 API를 QuotaBeacon이 직접 호출

- GLM 사용률에 존재하지 않는 reset 시각을 추정
- ZHIPU 중국 계정 지원과 다른 Provider 리팩터링

## 확인된 원인과 권장 결정

- QuotaBeacon 조립부가 Z.ai를 항상 `StateOnlyProvider(.unsupportedContract)`로 생성해 연결 시도 자체가 없었다.
- 연결 GUI도 Z.ai를 요청 Provider에서 제외하고 opt-in control을 제공하지 않았다.
- 현재 GLM 로그인은 독립 `glm`/`zai` CLI가 아니라 `~/.zshrc`의 `claude-glm` alias에 `ANTHROPIC_BASE_URL`과 `ANTHROPIC_AUTH_TOKEN`이 들어 있는 형태다.
- 공식 `glm-plan-usage` plugin은 최초 조사 시 미설치였으며, 공식 marketplace에서 version `0.0.1`을 설치했다.
- 공식 script를 기존 profile로 redacted 1회 probe한 결과 ZAI platform과 월간 MCP·5시간 token quota가 반환됐고 profile hash/mtime은 불변이었다.
- 권장 구현은 endpoint·credential을 제품에 복제하지 않고, 설치된 공식 plugin script와 기존 GLM profile을 동적으로 발견해 script를 1회 실행하는 `observed · Beta` bridge다.
