## 문서 기반 제약 사항

- 외부 package dependency를 추가하지 않고 Foundation·AppKit·Security 및 기존 Infrastructure만 사용한다.
- Codex credential 접근은 기존 read-only opt-in 이후에만 허용한다. opt-in 전 자동 탐지는 executable metadata만 확인한다.
- 기본 성공 경로는 현재 검증된 공식 app-server RPC로 유지한다. 새 source는 기존 경로가 실패하거나 사용할 수 없을 때만 fallback한다.
- OAuth fallback은 access token만 메모리에서 선택하고 refresh token을 읽거나 사용하지 않는다. endpoint allowlist·redirect 거부·cache 금지·timeout·backoff를 적용한다.
- CLI status fallback은 모델 실행이나 사용자 session 기록을 만들지 않는 격리 환경에서만 허용한다. 이를 증명하지 못하면 해당 fallback은 출하하지 않는다.
- raw payload·token·이메일·계정 ID·홈 경로를 history, export, diagnostic, fixture에 저장하지 않는다.
- 기존 `codex.executablePath`와 `codex.readOnlyEnabled` 설정은 migration 없이 계속 동작해야 한다.

## 회귀 0 릴리스 원칙

- 여기서 `회귀 0`은 구현 전 기준선과 비교해 자동화·수동 검증에서 발견된 기존 기능 회귀가 0건임을 의미한다.
- 구현 전 전체 test/build/설치본 snapshot을 기준선으로 고정하고 실패가 있으면 먼저 원인을 분리한다.
- 기존 테스트를 삭제하거나 기대값을 느슨하게 만들지 않는다. 불가피한 변경은 동작 계약 변경 근거와 동등 이상 assertion을 남긴다.
- Phase별 자체 테스트가 끝나지 않으면 다음 Phase로 이동하지 않는다.
- Claude·Grok·Gemini·GLM 중 하나라도 LIVE/typed-state 계약이 달라지면 Codex 변경을 출하하지 않는다.
- Debug와 Universal Release build, 전체 unit/UI test, 설치본 upgrade·재시작·login-item 실행 검증이 모두 통과해야 한다.
- 실계정 검증 전후 credential/config hash·mtime·mode 변경은 0이어야 한다.
- 알려진 회귀가 남으면 완료나 push로 표시하지 않고 해당 Phase에서 수정하거나 rollback한다.
