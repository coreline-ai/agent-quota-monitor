## 개발 목적

메뉴바 상주 앱의 실제 물리 메모리와 새로고침 시 최고 메모리를 낮춘다. 전체 History 상주·복사·JSON 재인코딩과 사용하지 않는 dashboard 선행 생성을 우선 제거하고, 30일 추세 품질과 Provider 수집 계약은 유지한다.

## 개발 범위

- History를 30일·8MiB 범위로 제한하고 5분 관측 bucket으로 압축한다.
- window가 없는 실패 표본과 동일 관측 캐시 표본을 History에서 제외한다.
- reset instance가 달라지면 같은 bucket에서도 별도 표본으로 보존한다.
- scheduled refresh에서 의미 있는 새 표본이 없으면 History JSON 쓰기와 `@Published history` 재할당을 생략한다.
- 기존 History는 최초 load에서 압축한 뒤 같은 schema로 다시 저장한다.
- dashboard window를 사용자가 처음 열 때 생성한다.
- Trends의 전체·선택 Provider chart model을 SwiftUI body 평가마다 재계산하지 않고 입력 변경 시에만 갱신한다.
- 기존 24시간·7일·30일 추세 범위와 first/minimum/last 화면 downsample은 유지한다.

## 제외 범위
